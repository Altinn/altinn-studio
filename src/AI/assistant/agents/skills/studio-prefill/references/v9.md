## In v9 apps

- **Carry stateless values into the instance** with `queryParameters` on the `InstantiationButton` in the stateless
  form. Each entry is `"<field in the instance's data model>": <expression>`, and the expression usually reads the
  stateless data model. The button sends the values as prefill when it creates the instance. The app writes them into
  the data models it creates at the first task, before `prefill.json`.

  ```json
  {
    "id": "start",
    "type": "InstantiationButton",
    "textResourceBindings": { "title": "start.button" },
    "queryParameters": { "soker.stilling": ["dataModel", "stilling"] }
  }
  ```

  v9 has no `mapping` on the `InstantiationButton`. `studioctl app upgrade v9` converts it to `queryParameters`.

- **`UserProfile` at task start.** A v9 app starts tasks in callbacks from the workflow engine, which run as the
  app and not as the user. The app therefore skips `UserProfile` when it prefills at task start, and logs an error.
  `ER` and `DSF` still work there. `UserProfile` works where the user's own request creates the element: a stateless
  form, a subform entry the user adds, and form data sent in the user's instantiation request.
