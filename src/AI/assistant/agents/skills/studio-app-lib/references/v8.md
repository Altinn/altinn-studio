# C# extension points in v8 apps

## Interfaces that have other names in v9

| Job | Interface | Namespace |
| --- | --- | --- |
| Run code when a task starts | `IProcessTaskStart` | `Altinn.App.Core.Features` |
| Run code when a task ends | `IProcessTaskEnd` | `Altinn.App.Core.Features` |
| Run code when a task is abandoned | `IProcessTaskAbandon` | `Altinn.App.Core.Features` |
| Run code when the process has ended | `IProcessEnd` | `Altinn.App.Core.Features` |
| Work the app does on its own in the process | `IServiceTask` | `Altinn.App.Core.Internal.Process.ProcessTasks.ServiceTasks` |
| File analyzer: read facts from an uploaded file | `IFileAnalyser` | `Altinn.App.Core.Features.FileAnalysis` |

## Process hooks

- The app runs every registered hook for every task. Compare the task ID the method gets with the tasks the code is
  for, and return at once for the others.
- Several classes can implement the same hook. The app runs them all.
- A hook gets the `Instance`, not a data accessor. Read and save data through the clients you inject, such as
  `IDataClient`.

## Service tasks and task types of your own

- An `IServiceTask` has `Type` and `Execute(ServiceTaskContext)`, which returns a `ServiceTaskResult`. Change data
  through `context.InstanceDataMutator`. The app saves the changes when `Execute` returns success.
- `IProcessTask` has `Type` and the methods `Start`, `End` and `Abandon`. They are optional from 8.9.0. In older
  versions, implement all three.
- The user who moves the process on needs a policy action named after the task's `Type`. That holds for a service
  task too, since the app moves on from it as that user. Built-in service tasks need `write`. The `studio-policy`
  skill writes the rule.

## Exclusive gateways

From 8.5.0 the app calls the `FilterAsync` overload that gets an `IInstanceDataAccessor`. Put the logic there. The
compiler also requires the obsolete overload without the accessor. The app does not call it once you override the
other one, so let it throw `NotSupportedException`.

## Package versions

Some interfaces and members arrived during v8. Check the `Altinn.App.Core` version in `App/App.csproj` before you
use one:

| Interface or property | From version |
| --- | --- |
| `IProcessTask` | 8.1.0 |
| `IOrderDetailsCalculator`, `IPaymentProcessor` | 8.2.1 |
| `IExternalApiClient` | 8.2.8 |
| `IDataWriteProcessor`, `IValidator` | 8.5.0 |
| `ISigneeProvider`, `IProcessEnd`, `IValidateQueryParamPrefill` | 8.6.0 |
| `CustomTextParameters` on `ValidationIssue` and `InstantiationValidationResult` | 8.7.0 |
| `IServiceTask` in the namespace above, for the app's own service tasks | 8.9.0 |
| Default bodies for `Start`, `End` and `Abandon` on `IProcessTask` | 8.9.0 |
| `ICopyInstanceValidator` | 8.12.2 |

When the app needs a newer interface, raise `Altinn.App.Api` and `Altinn.App.Core` together to the same 8.x
version. The `studio-app-development` skill covers the app version.

## Interfaces that v9 removes

- `IPageOrder` is obsolete and does nothing with app frontend 4, which v8 apps use. Hide pages with an expression
  instead (the `studio-layouts` skill).
- `IPdfFormatter` is obsolete. Leave pages and components out of the PDF with `excludeFromPdf` in the layout
  settings instead (the `studio-layouts` skill).
- `IEventHandler` receives Altinn Events. It works in v8, but v9 removes the endpoint it hangs on. The
  `studio-integrations` skill covers events.

Do not add new code on these.

## Method names

Many methods end in `Async`, such as `IAppOptionsProvider.GetAppOptionsAsync`, `IDataListProvider.GetDataListAsync`
and `IProcessExclusiveGateway.FilterAsync`. v9 drops the suffix.

## Source and docs

- The v8 source is [Altinn/app-lib-dotnet](https://github.com/Altinn/app-lib-dotnet). Pick the tag that matches the
  package version, such as `v8.12.15`, and read the interface under `src/Altinn.App.Core`.
- [Definer egendefinerte prosess hooks](https://docs.altinn.studio/nb/altinn-studio/v8/reference/configuration/process/pre-post-hooks/):
  the three task hooks. It does not cover `IProcessEnd`.
- [Egendefinert systemoppgave](https://docs.altinn.studio/nb/altinn-studio/v8/guides/development/service-tasks/custom/):
  an `IServiceTask` with its registration, BPMN element and policy action.
- [Exclusive Gateways](https://docs.altinn.studio/nb/altinn-studio/v8/reference/configuration/process/exclusive-gateways/):
  `IProcessExclusiveGateway` and the gateway in `process.bpmn`.
