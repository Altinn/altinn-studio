# Code lists in v9 apps

## Altinn.Codelists

A v9 app needs Altinn.Codelists 9.0.0-preview.2 or later. 8.x does not work, and with 9.0.0-preview.1
`AddAltinnCodelists()` throws a `TypeLoadException` as the app starts. `studioctl app upgrade v9` does not change the
package for you. The docs page on shared code lists says to use 9.0.0-preview.1, which is wrong.

## Code list providers

The methods have no `Async` suffix: `IAppOptionsProvider.GetAppOptions` and
`IInstanceAppOptionsProvider.GetInstanceAppOptions`. The docs page on dynamic code lists shows the names with `Async`.

## When the form opens

The app sends options with the form when it opens, and the frontend fetches only the rest. The order then differs
from the one for the options endpoint:

- For an `optionsId` with a file in `App/options/`, the app sends the file, even when a provider has the same ID.
- For any other `optionsId` on a component without `queryParameters`, the app asks the code list providers. In an
  instance it tries `IInstanceAppOptionsProvider` first, whether or not the component has `secure`.
- The frontend fetches from the options endpoint only for a component with `queryParameters`, or when the app sent
  nothing for the ID, as for a library code list.

A file and a provider with the same ID can therefore give one component different options than another. Keep every
ID unique. Set `secure` anyway on a component that uses an `IInstanceAppOptionsProvider`, since the frontend needs it
whenever it fetches the list.

## Options files

- The folder is always `App/options/`.
- The app reads the files when it starts. A file that is not valid JSON stops the app from starting, and the error
  lists the file.
- The file name must match the `optionsId` exactly, including case, on every operating system.

## Docs

- [Gjenbruke kodelister fra organisasjonsbiblioteket](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/look-and-feel/options/sources/organisation-library/):
  importing a copy of a library code list into `App/options/`. The page does not cover the `lib**` reference, which
  v9 apps also support.
- [Kodelister fra repeterede strukturer](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/look-and-feel/options/sources/from-data-model/):
  `source` with its paths and labels.
- [Kodelister og svaralternativer](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/look-and-feel/options/): every
  source, with filtering, sorting, preselection and what is saved in the data model.
- [Felles standard kodelister](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/look-and-feel/options/sources/shared/):
  the IDs in Altinn.Codelists, and the methods that register one source or one SSB classification.
- [Dynamiske kodelister](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/look-and-feel/options/sources/dynamic/):
  code list providers, query parameters and secure options.
