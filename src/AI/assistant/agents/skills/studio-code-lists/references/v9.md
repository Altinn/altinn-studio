# Code lists in v9 apps

## Altinn.Codelists

A v9 app needs an Altinn.Codelists 9.x release that is built for the app's `Altinn.App.Core` version. Altinn.Codelists
8.x does not work in a v9 app, and `studioctl app upgrade v9` does not change the package for you.

The code list providers in the package must implement `GetAppOptions`, which `Altinn.App.Core` 9.0.0-preview.8
renamed from `GetAppOptionsAsync`. A release built before that throws a `TypeLoadException` that says `GetAppOptions`
has no implementation. `AddAltinnCodelists()` throws it as the app starts, so the app does not start at all.

- Altinn.Codelists 9.0.0-preview.1 works with `Altinn.App.Core` 9.0.0-preview.5 to 9.0.0-preview.7, not later.
- Check [Altinn.Codelists on NuGet](https://www.nuget.org/packages/Altinn.Codelists) for a newer 9.x release, and
  its changelog in the package source.
- When the app is on a newer `Altinn.App.Core` than any Altinn.Codelists release supports, tell the user. Until a
  release supports it, use an options file, a library code list or a code list provider of the app's own.

The docs page on shared code lists says to use 9.0.0-preview.1, which is wrong for apps on 9.0.0-preview.8 or later.

## Code list providers

The methods have no `Async` suffix: `IAppOptionsProvider.GetAppOptions` and
`IInstanceAppOptionsProvider.GetInstanceAppOptions`. The docs page on dynamic code lists still shows the v8 names.

## When the form opens

The app sends options with the form when it opens, and the frontend fetches only the rest. The order then differs
from the one for the options endpoint:

- For an `optionsId` with a file in `App/options/`, the app sends the file, even when a provider has the same ID.
- For any other `optionsId` on a component without `queryParameters`, the app asks the code list providers. In an
  instance it tries `IInstanceAppOptionsProvider` first, whether or not the component has `secure`.
- The frontend fetches from the options endpoint only for a component with `queryParameters`, or when the app sent
  nothing for the ID, as for a library code list.

A file and a provider with the same ID can therefore give one component different options than another. Keep every
ID unique. Set `secure` anyway on a component that uses an `IInstanceAppOptionsProvider`, since the frontend needs it
whenever it fetches the list.

## Options files

- The folder is always `App/options/`.
- The app reads the files when it starts. A file that is not valid JSON stops the app from starting, and the error
  lists the file.
- The file name must match the `optionsId` exactly, including case, on every operating system.
