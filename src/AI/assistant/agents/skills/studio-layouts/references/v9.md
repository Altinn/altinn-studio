## UI folders

`App/ui/<taskId>/` holds the pages of the task `<taskId>`. The folder name equals the task's ID in `process.bpmn`
exactly, including case. There is no `layout-sets.json`, and the app ignores one. A leftover `layout-sets.json` means
that the upgrade to v9 did not finish. Tell the user.

`defaultDataType` at the top of the folder's `Settings.json` names the data type in `applicationmetadata.json` that
the pages bind to:

```json
{
  "$schema": "https://altinn.studio/designer/app-dist/9.0.0-preview.9/schemas/json/layout/layoutSettings.schema.v1.json",
  "pages": { "order": ["Side1"] },
  "defaultDataType": "model"
}
```

Always set `defaultDataType`. Without it the app cannot show the folder's pages.

When you add a task that shows pages, add its folder. When you rename a task, rename its folder. The `studio-process`
skill covers tasks, and the folders of service tasks.

Three kinds of folder are not named after a task. Each still needs `defaultDataType`:

- A subform's folder takes any name. See below.
- A stateless start page is the folder that `onEntry.show` in `applicationmetadata.json` names. The
  `studio-app-settings` skill covers stateless apps.
- A custom receipt is the folder `App/ui/CustomReceipt/`. Its `defaultDataType` needs a data element on the instance.

## Settings for the whole app

`App/ui/Settings.json` holds settings for every task, such as `taskNavigation`, `showLanguageSelector` and
`autoSaveBehavior`. The file is flat: the keys sit at the root. Under a `pages` key the app ignores them, with no error.

The same keys under `pages` in a task's `Settings.json` override them for that task. The app reads a task's settings
through a fixed model and drops what the model lacks, although the schema allows it:

- `validationOnNavigation`, `navigationTitle` and `hideAppNameInPdf` work only in `App/ui/Settings.json`.
  `validationOnNavigation` also works on a page, as `data.validationOnNavigation`.
- `expandedByDefault` on a page group has no effect.

## The layout schema

v9 apps name the schemas that Altinn Studio publishes for each release of the app libraries:

```text
https://altinn.studio/designer/app-dist/<version>/schemas/json/layout/layout.schema.v1.json
```

- `<version>` is the version of `Altinn.App.Api` in `App/App.csproj`, such as `9.0.0-preview.9`. `Settings.json` uses
  `layoutSettings.schema.v1.json` in the same folder.
- The schemas are generated from the app frontend. Their source is
  [src/common/ts/layout-contract/schemas/json/layout](https://github.com/Altinn/altinn-studio/tree/main/src/common/ts/layout-contract/schemas/json/layout)
  in the Altinn Studio repository.
- The v9 docs pages show `$schema` URLs on `altinncdn.no`. Those serve the v8 schema, which lacks `Heading` and has
  the v8 property names. Do not use them in a v9 app.

## Components and defaults that differ from v8

Copying a component from a v8 app or a v8 docs page breaks in these places:

- Headings are `Heading`. `Header` does not exist.
- `FileUpload` takes `optionsId` for files the user tags. `FileUploadWithTag` does not exist.
- The organization lookup is `OrganizationLookup`.
- Binding keys and text keys are camelCase: `ssn` and `fullName` on `PersonLookup`, `orgnr` and `name` on
  `OrganizationLookup`, and `addButton` and `saveButton` on `RepeatingGroup`.
- A button that starts an instance is `InstantiationButton`, which sends prefill with `queryParameters`. It has no
  `mapping`, and `Button` has no `mode`.
- `NavigationButtons` shows the back button by default. Set `"showBackButton": false` to hide it.
- `Datepicker` stores a date only, unless you set `"timeStamp": true`. Set it only for a field with
  `"format": "date-time"` in the data model. `format` takes Unicode tokens, such as `dd.MM.yyyy`. `DD.MM.YYYY` does
  not work.
- Fields that are not required show the marker "Valgfritt". Set `labelSettings.optionalIndicator` to `false` to hide
  it.
- `required` and `readOnly` exist only on components that take input. The schema shows which.
- There are no `RuleConfiguration.json` or `RuleHandler.js` files. Never create them.

`studioctl app upgrade v9` makes these changes in an upgraded app. The upgrade docs list most of the changes it
makes, but not the ones to `FileUploadWithTag` and `Datepicker`.

## The PDF of a task

A PDF task that lists a task in `autoPdfTaskIds` prints that task's pages and leaves out what its `excludeFromPdf`
lists, but it ignores the task's `pdfLayoutName`. A task's own `pdfLayoutName` applies only where the app renders a PDF
at that task: the PDF preview, and the PDF that a signing or payment task makes of itself. For a PDF task's PDF of a
page of your own, give the PDF task a folder with `pdfLayoutName`, as the `studio-process` skill describes.

## Summary2 of another task

With `taskId` in the target, the frontend reads the folder `App/ui/<taskId>/` and its `defaultDataType`. When that
folder does not exist, Summary2 looks for the target in the current task instead.

## Subforms

A subform's folder takes any name. Its `Settings.json` has the subform's data type as `defaultDataType`. The `Subform`
component's `layoutSet` is the folder name.

`"type": "subform"` in the folder's `Settings.json` is a marker that only Studio reads. The app ignores it. Studio
also recognizes a folder as a subform when a `Subform` component opens it, so a new subform does not need the marker.
Do not remove one that is there.

The v9 subform docs page shows `$schema` on `altinncdn.no` in its example. Use the app-dist URL above.
