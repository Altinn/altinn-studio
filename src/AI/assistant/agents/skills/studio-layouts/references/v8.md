# Layouts in v8 apps

v8 apps run app frontend 4.

## Layout sets

`App/ui/layout-sets.json` ties each UI folder to its tasks and its data model:

```json
{
  "$schema": "https://altinncdn.no/toolkits/altinn-app-frontend/4/schemas/json/layout/layout-sets.schema.v1.json",
  "sets": [{ "id": "form", "dataType": "model", "tasks": ["Task_1"] }],
  "uiSettings": {}
}
```

- `id` is the folder name under `App/ui/`.
- `dataType` is the data type in `applicationmetadata.json` that the pages bind to.
- `tasks` lists the process tasks that show the set's pages. A set can serve several tasks. List each task in one set
  only.
- A new task that shows pages needs a set and a folder. The `studio-process` skill covers tasks.

Three kinds of set list no process task:

- A subform's set has no `tasks`. See below.
- A stateless start page is the set that `onEntry.show` in `applicationmetadata.json` names, with no `tasks`. The
  `studio-app-settings` skill covers stateless apps.
- A custom receipt is a set with `"tasks": ["CustomReceipt"]`. Its `dataType` needs a data element on the instance.

## Settings for the whole app

`uiSettings` in `layout-sets.json` holds settings for every task, such as `taskNavigation` and
`showLanguageSelector`. Most of the same keys under `pages` in a set's `Settings.json` override them for that set.

`validationOnNavigation` can go in `uiSettings`, under `pages` in a set's `Settings.json`, or on a page as
`data.validationOnNavigation`. The navigation components have keys of their own: `validateOnNext` and
`validateOnPrevious` on `NavigationButtons`, `validateOnForward` and `validateOnBackward` on `NavigationBar`, and
`validation` on each `CustomButton` action. The `studio-validation` skill covers how they combine.

## The layout schema

Use these URLs in `$schema`, and read the layout schema there:

- Layout files: `https://altinncdn.no/toolkits/altinn-app-frontend/4/schemas/json/layout/layout.schema.v1.json`
- `Settings.json`: the same folder, `layoutSettings.schema.v1.json`

Studio writes `https://altinncdn.no/schemas/json/layout/layout.schema.v1.json` in the pages it creates. That URL
serves an older schema that lacks `RepeatingGroup`, `Summary2`, `Subform` and many other components. Do not read it,
and replace it with the URL above in files you change. Some apps pin a release, such as
`.../altinn-app-frontend/4.25.1/...`. The `4` path follows the newest release of app frontend 4.

## Components and defaults that differ from v9

Copying a component from a v9 app or a v9 docs page breaks in these places:

- Headings are `Header`. `Heading` does not exist.
- `FileUpload` takes no options. A file upload where the user tags each file is `FileUploadWithTag`, with
  `optionsId`.
- The organization lookup is `OrganisationLookup`.
- Binding keys and text keys are snake_case: `person_lookup_ssn` on `PersonLookup`, `organisation_lookup_orgnr` on
  `OrganisationLookup`, and `add_button` and `save_button` on `RepeatingGroup`.
- `InstantiationButton` sends prefill with `mapping`, from paths in the stateless data model to paths in the new
  instance's data model. `Button` also takes `mode`: `submit` (the default), `save` or `instantiate`. Use
  `InstantiationButton` to start an instance, which v9 also has.
- `NavigationButtons` shows only the next button. Set `"showBackButton": true` to show the back button too.
- `Datepicker` stores a date and time unless you set `"timeStamp": false`. A field with `"format": "date"` in the
  data model needs `false`, and the frontend reports a mismatch. Write `format` with the tokens `dd.MM.yyyy`.

When Studio adds a PDF task, it writes a page named `ServiceTask` with a component of type `Heading` into the task's
folder. v8 has no `Heading`, so change that type to `Header`.

## The PDF of a task

When a task ends and one of its data types with a `classRef` has `enablePdfCreation: true`, the app makes a PDF of the
task's set. That PDF reads the set's `pdfLayoutName` and `excludeFromPdf`. A PDF task that lists the task in
`autoPdfTaskIds` reads neither, and prints every page of the task that is not hidden.

## Old rule files

`RuleConfiguration.json` and `RuleHandler.js` in a set's folder hold JavaScript rules from before expressions. Do not
add rules. Use an expression or C# instead (the `studio-expressions` skill). v9 removes the files.

## Summary2 of another task

With `taskId` in the target, the frontend uses the set that lists that task in `tasks`, and that set's `dataType`.

## Subforms

The subform's set in `layout-sets.json` has the folder name as `id`, the subform's data type as `dataType`, and no
`tasks`. The `Subform` component's `layoutSet` is the set's `id`.

Studio adds `"type": "subform"` to a subform's set, and reads it to treat the set as a subform, for example to put a
close button on each new page. The app does not read it. The key is outside the layout-sets schema, so the file no
longer validates against its own `$schema`. Keep the key where Studio put it.

The v8 subform guide says to set `appLogic.allowInSubform` to `true` in `applicationmetadata.json`. Neither app
frontend 4 nor the app library reads it.
