# Policy in v9 apps

## The service owner's rights

The v9 workflow engine moves the instance as the service owner, not as the user. Storage checks those calls
against this policy, with `urn:altinn:org` as the subject. In a rule that is not scoped to a task, the policy must
give the service owner (`urn:altinn:org` = `[org]`):

- `read` and `write`, always
- `complete`, when the app confirms instances as complete
- `delete`, when `applicationmetadata.json` makes the app delete instances when the process ends

For the workflow engine, the service owner needs no action for a task type, such as `confirm` or `reject`. Storage
always lets the service owner save a process transition. The payment guide says what the service owner needs on a
payment task.

The template's service owner rule gives `read`, `write`, `instantiate` and `complete`. Keep it when you change other
rules.

## Build checks

Building the app checks the service owner's rights:

- The build fails when the policy does not give the service owner a right the app needs.
- The build warns when it cannot tell. A right given only in a rule scoped to a task causes it, and so does a Deny
  rule or a condition. Give the rights in a rule without a task.

## Service tasks

The process stops on each service task while the workflow engine runs it. While the instance is there, the app
checks users against the service task's ID:

- `read` to see the instance
- `write` to retry the task when it fails

Every service task accepts `write`, built-in or defined by the app. A user rule scoped to the task before a service
task does not cover the service task. Name the service task in the rule as well, or use a rule without a task.

## Before you finish

The service owner gets every right in the list at the top from a rule that is not scoped to a task, with no
condition and no Deny rule against it. Then the build neither fails nor warns about the service owner's rights.

## Docs

- [Definere autorisasjonspolicy](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/reference/configuration/authorization/):
  the obligation for authentication level and API scopes. Its events attribute is wrong (see `SKILL.md`), and it
  does not cover access packages.
- [Regelbibliotek](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/reference/configuration/authorization/rules/):
  example rules scoped to a task or an end event, for events and for authentication levels. They use roles, not access
  packages.
- [Signering](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/process/signing/) and
  [Betaling](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/process/payment/): the actions that
  signing and payment tasks need, for users and the service owner.
