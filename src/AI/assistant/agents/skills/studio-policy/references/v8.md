# Policy in v8 apps

## Service tasks

The app moves the process with the user's token. When the user moves on from a task, the app runs the service
tasks that follow in the same request, and checks the user's rights again for each one:

- A built-in service task (`pdf`, `eFormidling`, `fiksArkiv`, `subformPdf`) needs `write` on that task.
- A service task type the app defines needs an action named exactly like the type. `write` does not grant it.

So a user rule scoped to tasks must also name every service task the instance passes on the way to the next user
task. A rule without a task covers them all.

## The service owner

The template has a rule that gives the service owner (`urn:altinn:org` = `[org]`) `read`, `write`, `instantiate` and
`complete`. The service owner uses it to work with instances through the app's API. Keep it when you change other
rules.
