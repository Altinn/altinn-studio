## In v9 apps

- **A data type's tasks** are the list in `taskIds`, such as `"taskIds": ["Task_1"]`. v9 no longer reads `taskId`.
  A data type with a `taskId` fails the build with ALTINNAPP0603, or gets ALTINNAPP0604 next to `taskIds`. Replace
  each `taskId` you find with `taskIds`.
- The app refuses to create, change or delete data of a type outside the tasks in its `taskIds`, also for the app's
  own C# code. List every task that changes the data. A data type without `taskIds` belongs to no task: users can
  change it in every task, and the app neither creates nor validates it.
- **A task's default data model** is `defaultDataType` in the task's `App/ui/<task id>/Settings.json`. Bindings,
  text variables and expressions without a data type id read this model. When you connect a model to a task by hand,
  add the task to the data type's `taskIds` and set `defaultDataType`.

  ```json
  {
    "pages": { "order": ["Side1"] },
    "defaultDataType": "soknad"
  }
  ```

- Without `defaultDataType`, the app backend falls back to the first data type in `applicationmetadata.json` that
  has a `classRef`, which can belong to another task. Always set it.
