# Validation in a v8 app

## Turn on the backend checks

In v8, `RequiredValidation`, `ExpressionValidation` and `RemoveHiddenData` under `AppSettings` in
`App/appsettings.json` are `false` by default, and the app template does not set them. Without the first two,
`process/next` checks neither required fields nor validation files, and an API client can submit data that breaks
them. Turn both on when the app has required fields or a validation file:

```json
{
  "AppSettings": {
    "RequiredValidation": true,
    "ExpressionValidation": true
  }
}
```

The backend then evaluates every `hidden` and `required` expression and every validation file. Check them for
frontend-only functions first, as the `studio-expressions` skill describes.

The backend checks required fields only in tasks whose layout set lists the task in `App/ui/layout-sets.json`.

## Hidden fields and the data model check

With `RemoveHiddenData` off, the backend also checks the C# attributes on fields that hidden components bind. A value
the user entered before the field was hidden can stop the submit, and the user sees the error only in the error
summary. With `RemoveHiddenData` on, the check skips those fields, and the app deletes their data when the task ends.
Turn it on only when the app may delete that data.

## What the user sees

- The error summary shows whenever there are visible errors, also while the user fills in the form.
- There is no `Invalid` validation type. Input the app cannot store, such as text in a number field, shows as a
  `Schema` message.
- When a C# issue names a `CustomTextKey` that the text resources lack, the frontend shows the key itself.

## Files

The validation file uses the schema
`https://altinncdn.no/toolkits/altinn-app-frontend/4/schemas/json/validation/validation.schema.v1.json`.

The page [ValidationHandler.cs](https://docs.altinn.studio/nb/altinn-studio/v8/repos/structure/validationhandler/)
describes a file that apps do not have. Ignore it.
