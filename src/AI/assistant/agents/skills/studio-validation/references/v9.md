# Validation in a v9 app

## The backend checks are on by default

In v9, `RequiredValidation`, `ExpressionValidation` and `RemoveHiddenData` under `AppSettings` in
`App/appsettings.json` are `true` by default. Leave them out. Setting one to `false` turns that check off on
`process/next`, so the rule then runs only in the browser.

The [expression validation page](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/data/validation/expression-validation/)
says the backend runs the rules only after you set `ExpressionValidation` to `true`. That is wrong for v9.

The backend checks required fields against the pages in the task's UI folder, `App/ui/<taskId>/`.

## What the user sees

- The error summary shows only after the user has tried to submit, or to change page where the app checks the page.
  When the user fixes the errors, it goes away until the next attempt.
- The validation type `Invalid` covers input the app cannot store in the data model, such as text in a number field.
  `AllExceptRequired` includes it. The user cannot leave a subform while such input remains.
- When a C# issue names a `CustomTextKey` that the text resources lack, the frontend shows `Description` instead,
  then `Code`.

## Files

The validation file uses the schema
`https://altinn.studio/designer/app-dist/<version>/schemas/json/validation/validation.schema.v1.json`. Use the
version the app's layout files use.
