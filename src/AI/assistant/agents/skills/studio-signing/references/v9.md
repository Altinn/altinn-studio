# Signing in v9 apps

- The app refuses to start when a signing task:
  - has no `signatureConfig` or no `signatureDataType`
  - sets only one of `signeeProviderId` and `signeeStatesDataTypeId`
  - has a `signeeProviderId` that no registered `ISigneeProvider` has, or that more than one has
  - uses user-controlled signing without a `correspondenceResource` for the current environment, in Staging and
    Production. Development logs a warning instead.
  - in Development, names a signature or signee-states data type that is missing or not app-owned
- The build rules catch most mismatches:
  - ALTINNAPP1013: the task names a data type that `applicationmetadata.json` does not declare
  - ALTINNAPP1015: a data type cannot hold what the task stores, such as a signature data type whose `taskId` is
    another task, or a signing PDF data type without `application/pdf`
  - ALTINNAPP1016: a signature or signee-states data type is not app-owned
  - ALTINNAPP1020: a required setting is missing, such as `dataTypesToSign` on a task that lists `sign`, or a
    `correspondenceResource` for an environment
  - ALTINNAPP1021: an element the app ignores, such as a misspelled one
- Nothing checks the policy: not `sign` for the signers, not `write` for the person who submits, and not the
  delegation rule.
- The signing task's pages are the UI folder `App/ui/<signing task id>/`. Its `Settings.json` needs a
  `defaultDataType`, or the frontend cannot show the task. The `studio-layouts` skill covers UI folders.
- `ref-data-as-pdf` comes only from a `pdf` service task before the signing task.
- The workflow engine starts the task in three steps: find the signees, delegate, notify. It retries a step that fails
  because a platform service is unavailable, and it does not notify anyone twice. When the task ends, the app revokes
  the delegated rights before it stores the signing PDF.
- Studio provisions the app's Maskinporten client with the service owner scopes. Add the Correspondence scope to that
  client in Studio. The `studio-integrations` skill covers Maskinporten.
- [Signing receipts](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/process/signing/how-to/correspondence-receipt/)
  shows how to set up the Correspondence resource and the receipt.

## Docs

- [Signing overview](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/process/signing/): what each
  kind of signing does and when to use it.
- [User-controlled signing](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/process/signing/how-to/runtime-delegated-signing/):
  `CommunicationConfig` and the default texts. Its setup steps, the delegation rule among them, show only in a
  browser.
- [Sign and submit](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/process/signing/how-to/sign-and-submit/):
  how to make the data task a signing task.
- [Role-based signing](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/process/signing/how-to/role-based-signing/):
  the guide for this kind. Its setup steps show only in a browser, so give users the link.
- [The signing task reference](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/reference/process/tasks/signing/): the
  signature object, unique signatures and how to verify a signature's hash.
- [API signing](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/process/signing/how-to/api-signing/):
  the calls and their responses.
