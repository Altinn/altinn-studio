# Expressions in a v9 app

## No RuleHandler.js or RuleConfiguration.json

A v9 app has no `RuleHandler.js` or `RuleConfiguration.json`, and neither the frontend nor the backend reads them.
Never create them. Show and hide with `hidden`, and compute values with calculations. If an upgraded app still has
these files, its old rules do nothing until you rewrite them.

## Calculations

`calculations` is a list, run in order: `{ "calculations": [{ "field": "total", "expression": [...] }] }`. The form
calculates before the user saves, and the backend on each save and on the data an instance is created with. A result
the field's type cannot hold is not written. A calculation that fails on the server is logged, and the field keeps
its value. The app does not start with the v8 format, an object keyed by field. The docs page says that only the
server calculates, after a save, which is wrong for v9.

## Lists and objects

The v9 frontend and backend both have `list`, `object`, `jmespath`, `sum`, `average` and `count`. `dataModel` and
`component` return lists and objects too, so an expression can work on all rows of a repeating group.

## The backend evaluates by default

`RemoveHiddenData`, `RequiredValidation` and `ExpressionValidation` are `true` by default in v9. So every `hidden`,
`hiddenRow` and `required` expression also runs on the backend when the user submits.

## Files

- Layouts are in `App/ui/<taskId>/layouts/<page>.json`. The `studio-layouts` skill covers UI folders.
- Layout and validation files use schemas under `https://altinn.studio/designer/app-dist/<version>/schemas/json/`.
  Keep the version the app's other files use.
