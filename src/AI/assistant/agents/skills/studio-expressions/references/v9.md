# Expressions in a v9 app

## No RuleHandler.js or RuleConfiguration.json

A v9 app has no `RuleHandler.js` or `RuleConfiguration.json`, and neither the frontend nor the backend reads them.
Never create them. Show and hide with `hidden`, and compute values in `calculation.json` or in C#. If an upgraded app
still has these files, its old rules do nothing until you rewrite them.

## Lists and objects

The v9 frontend and backend both have `list`, `object`, `jmespath`, `sum`, `average` and `count`. `dataModel` and
`component` return lists and objects too, so an expression can work on all rows of a repeating group. The
[function reference](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/expressions/reference/functions/)
has the arguments.

## The backend evaluates by default

These keys under `AppSettings` in `App/appsettings.json` are `true` by default in v9:

- `RemoveHiddenData`: the backend evaluates `hidden`, `hiddenRow` and `removeWhenHidden` and removes the data of
  hidden components when the task ends.
- `RequiredValidation`: the backend evaluates `required` and `hidden` and checks required fields on `process/next`.
- `ExpressionValidation`: the backend runs the validation files.

So every `hidden`, `hiddenRow` and `required` expression also runs on the backend when the user submits. A frontend
function or an error there stops the submit, even when the form looks right in the browser.

## Calculated fields

The v9 frontend runs `App/models/<dataTypeId>.calculation.json` in the browser as the user types, and the backend
runs it again when it saves the data. Use only functions both have.

## Files

- Layouts are in `App/ui/<taskId>/layouts/<page>.json`. The `studio-layouts` skill covers UI folders.
- Layout and validation files use schemas under `https://altinn.studio/designer/app-dist/<version>/schemas/json/`.
  Keep the version the app's other files use.
