## Maskinporten

A v9 app has exactly one Maskinporten identity: the client Studio creates for it. The platform provides its
credentials, as the Maskinporten page under Docs explains.

- Studio adds the service owner scopes to every v9 app when it builds the app. Do not add them yourself. Redeploying
  an older build does not give it a newly added scope.
- A `MaskinportenSettings` section has no effect, wherever it is. Delete it, and take any key in it out of the
  repository.
- A call to `ConfigureMaskinportenClient`, `MaskinportenSettingsFilepath` or `IFiksSetupBuilder.WithMaskinportenConfig`
  fails the build.
- A deployed app without credentials does not start. A local app starts, and fails at the first token request.
- `IMaskinportenClient`, `UseMaskinportenAuthorization` and `UseMaskinportenAltinnAuthorization` also take a
  `MaskinportenTokenRequest`, with `Scopes` and optionally `ConsumerOrg`, `Resource` or `SystemUser`.
- The client authenticates with a JWK only. A client that used a certificate needs a JWK.

### Local runs

On a local run, studioctl is the platform. It cannot hand over the client Studio created, so you supply a client for
it to provide in that client's place. This is a gap in the local setup, not a second identity for the app.

A person stores the local client with `studioctl app maskinporten set`, run in the app's folder. The app picks it up
without a restart. Until then the app starts, and its first token request fails with a log message that names the
command.

- Maskinporten grants scopes per client. The local client is a different registration from the deployed one, so a
  scope selected in Studio is not on the local client, and a scope on the local client is not on the deployed app.
  Give both the scopes the code requests.
- Register the local client where the API you call accepts it, normally `test.maskinporten.no`.
- The app libraries' own calls as the service owner go to localtest locally, so the local client does not need the
  service owner scopes for them. App code that requests those scopes itself still calls Maskinporten.

### Another Maskinporten client

`Altinn.ApiClients.Maskinporten` no longer comes with the app libraries. An app that uses it needs its own
`PackageReference`. Keep its settings out of a section named `MaskinportenSettings`, and its credentials in Key
Vault.

### Upgrading from v8

`studioctl app upgrade v9` reports the Maskinporten sections, code and scopes it finds, and changes none of them.
Add the scopes it lists to the app in Studio before the first deploy of the v9 build, or the deployed app fails at
its first token request. The report reads the scopes from those sections, so note them before you delete any.
[Kommer du fra v8?](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/integration/maskinporten/#fra-v8)
has the other steps.

## Correspondence

- Add `altinn:correspondence.write` in Studio. `CorrespondenceAuthenticationMethod.Default()` requests it together
  with the service owner scopes, `altinn:serviceowner` included. A resource your organization owns therefore needs no
  `write` rule for it.
- Set `WithIdempotentKey(Guid)` with a key that stays the same when the code runs again. A second send with the key
  fails with `409 Conflict`, which means the message is already sent. The key cannot be combined with several
  recipients.
- [Kommer du fra v8?](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/integration/correspondence/maskinporten/#kommer-du-fra-v8)
  lists the types and builder methods v9 removed, and what replaces them.

## Events

- The app can publish events but not receive them. Work the app did on an event belongs in a service task, which can
  wait for an answer from another system. The `studio-process` skill covers service tasks.
- Give `AddEvent` an idempotency key that stays the same each time the code runs for the same event and instance.
  [Sende dine egne hendelser](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/integration/events/#sende-dine-egne-hendelser)
  explains the key and who the app sends as.

## eFormidling

- The scopes it needs are the service owner scopes, which Studio adds to every v9 app. Add none.
- The service owner needs `complete` in the policy, because the task marks the instance complete. Without it the
  build fails with ALTINNAPP0800.
- Register with `services.AddEFormidling().WithMetadata<TMetadata>()`, from `Altinn.App.Core.EFormidling.Extensions`.
  Add `.WithReceivers<TReceivers>()` for your own receivers. Stopping after `AddEFormidling()` fails the build with
  ALTINNAPP0701.
- `GenerateEFormidlingMetadata` and `GetEFormidlingReceivers` take an `IInstanceDataAccessor`.
- The task waits for the delivery confirmation itself, for about two and a half hours. Remove a feedback task after
  it, and the event subscription the v8 setup needed.
- The app refuses to start when `EFormidlingClientSettings:BaseUrl` is missing where the task is enabled, or a
  required setting in `<altinn:eFormidlingConfig>` is missing for the environment. eFormidling cannot be tested
  locally yet, so set `<altinn:disabled env="development">true</altinn:disabled>`.
- `<altinn:eFormidlingConfig>` must be on the task. The `eFormidling` block in `applicationmetadata.json` and
  `AppSettings:EnableEFormidling` are gone. The `studio-app-settings` skill lists the build errors.

## Fiks Arkiv

- Fiks IO uses the app's Maskinporten client. There is nothing to point it at.
- The task waits for the archive's receipt, for up to seven days. Remove a feedback task after it.
- An exclusive gateway with at least two outgoing flows must follow the task, or the app refuses to start. The task
  moves on with `SuccessHandling.Action` after a receipt, and with `ErrorHandling.Action`, `reject` by default, when
  the archive cannot create the record. Moving the process on needs no grant in the policy.
- The service owner needs `complete` in the policy, because the task can mark the instance complete. Without it the
  build fails with ALTINNAPP0800. The `studio-policy` skill writes the rule.
- `MoveToNextTask` is gone. `SuccessHandling.MarkInstanceComplete` is `true` by default.
- `IFiksArkivMessageHandler`, registered with `.WithMessageHandler<T>()`, sees each message from the archive. It must
  not move the process. It replaces `IFiksArkivResponseHandler`, and `IFiksArkivHost` is gone.
