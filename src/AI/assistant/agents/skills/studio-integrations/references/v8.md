# Integrations in v8 apps

## Maskinporten

The built-in client reads the configuration section `MaskinportenSettings`: `authority`, `clientId`, and `jwkBase64`
or `jwk`. Fill it in one of two ways:

- **Studio provisions the client.** Add the scopes in Studio. When the app is deployed, the platform adds
  `MaskinportenSettings` to the app's configuration. Nothing goes in the repository. Do not also set `clientId`,
  `jwk` or `jwkBase64` under `MaskinportenSettings` yourself. Configuration merges key by key, and the result is a
  client ID and a key that belong to different clients.
- **The app has its own client** from Samarbeidsportalen. Put `authority` in `appsettings.Staging.json` and
  `appsettings.Production.json`, and the client ID and key in Key Vault as `MaskinportenSettings--ClientId` and
  `MaskinportenSettings--JwkBase64`. The app needs Key Vault as a configuration provider. To use another section,
  call `services.ConfigureMaskinportenClient("<section>")`.

Locally, nothing provisions a client. Give the app a test client from `test.maskinporten.no` with the same scopes, for
example in .NET user secrets under `MaskinportenSettings`.

- The British spellings `UseMaskinportenAuthorisation` and `UseMaskinportenAltinnAuthorisation` are obsolete. So is
  `IMaskinportenTokenProvider`. Use the `-ization` methods and `IMaskinportenClient`.
- Many apps use the separate package `Altinn.ApiClients.Maskinporten`, with `AddMaskinportenHttpClient` and settings
  such as `EncodedJwk`. The app libraries bring it along. Use the built-in client in new code. When Studio provisions
  the client, keep the package's settings out of a section named `MaskinportenSettings`.
- v9 drops the app's own client. If the app may be upgraded, prefer scopes in Studio.

## Correspondence

- The client needs version 8.12.2 or later of `Altinn.App.Api` and `Altinn.App.Core`.
- `CorrespondenceAuthenticationMethod.Default()` requests `altinn:serviceowner/instances.read`,
  `altinn:serviceowner/instances.write` and `altinn:correspondence.write`. Add these in Studio. It does not request
  `altinn:serviceowner`, so the resource's policy must grant your organization `write`, even for a resource it owns.
- The `CorrespondenceAuthorisation` enum and `WithSender` are obsolete. Use `CorrespondenceAuthenticationMethod`,
  and go straight from `WithResourceId` to `WithSendersReference`.
- v8 has no idempotency key for a correspondence. Code that runs again sends a new message.

## Receiving events

v8 apps can receive events from Altinn Events. An `IEventHandler` handles each event type, and returns `false` to
have Altinn Events try again. The app checks each delivery against the Key Vault secret
`EventSubscription--SecretCode`. The two events pages under Docs show the setup. v9 removes all of this, so do not
build new features on it if the app may be upgraded.

## eFormidling

- Add `altinn:serviceowner/instances.read` and `altinn:serviceowner/instances.write` in Studio. The delivery status
  check and the event subscription use them.
- There are two setups. Do not combine them:
  - **Service task**, from 8.9: an `eFormidling` task in the process with `<altinn:eFormidlingConfig>`. Use this one.
  - **Legacy**: the `eFormidling` block in `applicationmetadata.json`, with `sendAfterTaskId` naming the task after
    which the app sends, and `"EnableEFormidling": true` under `AppSettings`.
- Register the services with `services.AddEFormidlingServices2<TMetadata, TReceivers>(config)`, or
  `AddEFormidlingServices<TMetadata>(config)` without your own receivers. Both bind `EFormidlingClientSettings`.
- `IEFormidlingMetadata.GenerateEFormidlingMetadata(Instance)` and
  `IEFormidlingReceivers.GetEFormidlingReceivers(Instance, string? receiverFromConfig)` take the instance.
- The app learns the delivery status through Altinn Events, so it needs the secret and the subscription from
  [Receiving events](#receiving-events). A feedback task after the eFormidling task holds the instance until the
  status arrives.
- Locally, `EFormidlingClientSettings:BaseUrl` points at the local integration point, normally
  `http://localhost:9093/api/`.

## Fiks Arkiv

- Fiks Arkiv needs version 8.9 or later.
- Fiks IO uses the app's built-in Maskinporten client. `.WithMaskinportenConfig("<section>")` on the builder points
  that whole client at another section, the same as `ConfigureMaskinportenClient`.
- Implement `IFiksArkivResponseHandler`, registered with `.WithResponseHandler<T>()`, to act on the archive's answer.
- The task finishes as soon as Fiks IO has the message, so the process normally has a feedback task after it. When
  the archive answers, the default response handler moves the process on from there if
  `SuccessHandling.MoveToNextTask` is `true`, the default. `SuccessHandling.MarkInstanceComplete` is `false` by
  default. When the send fails, `ErrorHandling.MoveToNextTask` decides whether the process moves on with
  `ErrorHandling.Action`, `reject` by default.
