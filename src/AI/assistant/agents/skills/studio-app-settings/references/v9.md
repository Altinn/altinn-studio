## applicationmetadata.json

- Keep the `$schema` the file has, of the form
  `https://altinn.studio/designer/app-dist/<version>/schemas/json/application/application-metadata.schema.v1.json`.
- A stateless `onEntry.show` names a folder under `App/ui/`. `defaultDataType` in that folder's `Settings.json` names
  the stateless data type. Set `allowAnonymousOnStateless` on that data type.
- The app checks the file when it builds, and these errors stop the build:
  - [ALTINNAPP0600](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/reference/analysis/rules/altinnapp0600/):
    `"enablePdfCreation": true` on a data type. A PDF service task makes PDFs. The `studio-process` skill covers it.
  - [ALTINNAPP0601](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/reference/analysis/rules/altinnapp0601/):
    an `eFormidling` block. Configure an eFormidling service task, as the `studio-integrations` skill says.
  - ALTINNAPP0603: `taskId` on a data type. v9 binds a data type to its tasks with the list `taskIds`. Replace each
    one: `"taskIds": ["Task_1"]`. A `taskId` next to `taskIds` only gives the
    warning ALTINNAPP0604, but remove it too.
  - [ALTINNAPP0900](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/reference/analysis/rules/altinnapp0900/):
    two `presentationFields` or `dataFields` entries with the same `id` for the same data type.
  - [ALTINNAPP0901](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/reference/analysis/rules/altinnapp0901/):
    a `presentationFields` or `dataFields` entry whose `dataTypeId` no data type has.
  - [ALTINNAPP0902](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/reference/analysis/rules/altinnapp0902/):
    `autoDeleteOnProcessEnd: true` together with `preventInstanceDeletionForDays`.
  - ALTINNAPP0800: the policy does not grant the service owner what the app does as the service owner. With
    `autoDeleteOnProcessEnd: true` that includes `delete`. The `studio-policy` skill writes the rule.

## appsettings*.json

- These `AppSettings` switches are on by default: `RemoveHiddenData`, `RequiredValidation` and
  `ExpressionValidation`. Set one to `false` only when the app is not ready for it.
- The app APIs always refuse with `409 Conflict` to create, change or delete data of a type whose `taskIds` does not
  list the instance's current task. No setting turns this off. The usual cause is a component bound to the wrong data
  model, or a task missing from `taskIds`. Fix the binding or `taskIds`.
- v9 no longer reads these keys. Delete them where you find them:
  - `AppSettings`: `AppBasePath`, the folder and file name keys such as `ConfigurationFolder` and
    `ProcessFileName`, `BaseResourceFolderContainer`, `DefaultBootstrapUrl`, `RuntimeSecretsDirectory`,
    `EnableEFormidling` and `EnforceDataTypeTaskId`
  - `FeatureManagement:JsonObjectInDataResponse`
- Delete `GeneralSettings:HostName` too. The app still reads it, for example to check `returnUrl` and to tell
  whether it runs on localtest. The platform sets it through an environment variable in every environment, and
  studioctl does the same for a local run, so a value in `appsettings*.json` only goes stale. `appsettings.Local.json`
  loads after the environment variables, so a value there wins. Remove it there as well, for example the old
  `altinn3local.no`.
- `AppSettings:AppFrontendAssetBaseUrl` serves the frontend from another URL, and works only in Development.
- The app never reads its Maskinporten credentials or the codes it checks callbacks with from its own configuration.
  The platform provides them. The `studio-integrations` skill covers Maskinporten.

## Secrets

- `ISecretsClient` has `GetSecret(name)`.
- [Kjøre appen lokalt](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/reference/configuration/secrets/#kjøre-appen-lokalt)
  says where a local run reads secrets: the studioctl secrets folder, .NET user secrets and `App/secrets.json`. Keep
  `secrets.json` out of the repository.

## File scanning

The file scan messages have new text keys, and the app no longer reads texts under the v8 keys. Rename them as
[Egenskaper og tekstnøkler for virusskanning](https://docs.altinn.studio/nb/altinn-studio/v9/develop-a-service/data/attachments/reference/virusskanning/)
says.

## Upgrading from v8

`studioctl app upgrade v9` changes these files:

- `applicationmetadata.json`:
  - It moves the `eFormidling` block into an eFormidling service task after `sendAfterTaskId`, and drops `serviceId`.
    It leaves the block when that task or `process.bpmn` is missing.
  - It removes `enablePdfCreation`, and adds a PDF service task where it was `true`.
  - It renames `allowedContributers` to `allowedContributors`.
  - It adds `application/pdf` or `application/json` to the `allowedContentTypes` of the data types for generated
    files, when the list is not empty.
  - It changes `$schema`.
- `appsettings*.json`: it removes `AppSettings:EnableEFormidling` and turns its value into `disabled` on the new task.
  It removes `GeneralSettings:HostName`, `FeatureManagement:JsonObjectInDataResponse` and `moveToNextTask` from the
  Fiks Arkiv settings.
- It only reports the old `AppSettings` keys and `MaskinportenSettings` sections. Delete them yourself.
- It does not touch `onEntry`, `partyTypesAllowed`, `copyInstanceSettings`, `messageBoxConfig` or
  `disallowUserInstantiation`.
