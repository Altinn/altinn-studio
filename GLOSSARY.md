# Glossary

The terms we use for the Altinn domain. The [README](README.md#how-it-fits-together) says how the parts of Altinn
Studio fit together.

| Term                 | Meaning                                                                                                                                                                                                         |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Altinn 3             | The current Altinn: the apps built with Altinn Studio, and the Altinn Platform services they call.                                                                                                              |
| Altinn Platform      | The shared services that apps call, such as Storage, Authorization and Register. Each has its own [repository](docs/repositories.md#platform). localtest emulates them on a developer's machine.                |
| App                  | A digital service that a service owner builds with Altinn Studio, identified as `<org>/<app>`, such as `ttd/my-app`. Its source is one repository, created from the [app template](src/App/template/README.md). |
| App developer        | A person who builds apps, usually for a service owner. They read [docs.altinn.studio](https://docs.altinn.studio), not this repository.                                                                         |
| Application metadata | The app's `config/applicationmetadata.json`: its id, its data types and which parties may instantiate it. Storage keeps it as the app's `Application`.                                                          |
| Code list            | The values and labels for a choice, such as a dropdown. App code calls them options.                                                                                                                            |
| Component            | A building block on a page, such as an input, a dropdown or a button.                                                                                                                                           |
| Correspondence       | A message from a service owner to a party through Altinn Correspondence.                                                                                                                                        |
| Data element         | One piece of data in an instance, of one data type, such as the form data, an attachment or a PDF.                                                                                                              |
| Data model           | The schema of a data type's form data, as JSON Schema or XSD, with a generated C# class.                                                                                                                        |
| Data type            | A kind of data an instance can hold, declared in application metadata, such as form data or an attachment.                                                                                                      |
| eFormidling          | The national message exchange that apps can send instance data through.                                                                                                                                         |
| Expression           | A JSON expression in layouts and configuration that both the app frontend and the app backend evaluate.                                                                                                         |
| ID-porten            | The national login service for people.                                                                                                                                                                          |
| Instance             | One use of an app by an instance owner, such as one application for a permit. It holds the process state and the data elements. Its id is `<instance owner party id>/<guid>`. Not a running copy of the app.    |
| Instance owner       | The party an instance belongs to.                                                                                                                                                                               |
| Instantiation        | Creating an instance.                                                                                                                                                                                           |
| Maskinporten         | The national login service for machines, which systems use to call apps and Altinn APIs.                                                                                                                        |
| Party                | A person, an organization, a sub unit, a self-identified user or a bankruptcy estate in Register, which can own instances.                                                                                      |
| Policy               | The app's XACML rules in `config/authorization/policy.xml`, which say who may do what with its instances.                                                                                                       |
| Prefill              | Filling form data from Register, Profile or other sources when an instance is created.                                                                                                                          |
| Process              | The BPMN flow an instance moves through, in `config/process/process.bpmn`.                                                                                                                                      |
| Service owner (org)  | An organization that owns and runs apps, identified by a short `org` code, such as `ttd`. The [service owner registry](https://github.com/Altinn/altinn-cdn/blob/master/orgs/altinn-orgs.json) lists them.      |
| Service task         | A task the app runs without a user, such as generating a PDF or sending through eFormidling.                                                                                                                    |
| Stateless app        | An app, or the first page of one, that shows data without creating an instance.                                                                                                                                 |
| Subform              | A form whose entries are separate data elements, edited in a UI folder of their own and listed in the main form.                                                                                                |
| System user          | A machine identity that an organization owns, which a system logs in as through Maskinporten.                                                                                                                   |
| Task                 | A step in the process. Its type sets what happens: a user fills in data, confirms, signs or pays, or the app runs a service task.                                                                               |
| Text resource        | A translatable text with a key, in `config/texts/resource.<language>.json`.                                                                                                                                     |
| UI folder            | In a v9 app, `ui/<task id>/` holds the pages of one task, and each subform has a UI folder of its own. Say UI folder, not layout set, which is the v8 name.                                                     |
| User                 | A person using an app, logged in with ID-porten, acting for themselves or for a party they may represent.                                                                                                       |
